# AGENTS.md 管理

创建或更新面向 coding agent 的仓库说明，让未来的 agent 获得正确上下文，而不是一次性加载整个项目的全部细节。

## 核心原则

把 `AGENTS.md` 当作简洁的导航层，而不是文档垃圾桶。把所有任务都需要知道的规则放在最近适用的 `AGENTS.md`；把详细、条件性、子系统专用的说明下沉到被索引的支持文件或嵌套 `AGENTS.md`。

## 何时使用

以下请求应使用此 skill：
- 创建 / 初始化 / 编写 `AGENTS.md`
- 更新 / 刷新 / 审计已有 agent 指令
- 组织 monorepo 或包级别的 agent 指导
- 减少 agent 文档的上下文膨胀
- 创建或更新 `AGENTS.md` 引用的文件
- 遵循 https://agents.md/ 的指导

不要把它用于普通 README 写作，除非 README 会作为 agent 指令的来源。

## 工作流程

1. **先读再写**
   - 阅读目标范围内已有的 `AGENTS.md`。
   - 阅读这些文件引用或索引到的文件。
   - 检查项目文档和配置，用来验证命令、约定和工作流。
   - 保留明确的用户 / 项目指令，除非用户要求删除，或它们已经明显过时。

2. **选择作用域**
   - 根 `AGENTS.md`：仓库级概览、导航、共享命令、共享规则。
   - 嵌套 `AGENTS.md`：某个子树、包、服务、应用或领域的本地说明；更近的文件覆盖父级说明。
   - 被索引的支持文件：只有在特定场景才有用的详细指导。

3. **应用渐进披露**
   - 保持根文件简短、易扫读。
   - 把细节放到未来 agent 真正需要它的位置，而不是让每个 agent 都加载。
   - 优先链接稳定的源文档，而不是把长文档整段复制进 `AGENTS.md`。
   - 只有当细节足够多、具有条件性或只属于某个子树时，才创建支持文件；否则在 `AGENTS.md` 中保留简短条目。
   - 如果 `AGENTS.md` 链接到某个指令文件，要在同一次修改中创建或更新该文件。

4. **更新整套指令集**
   - 更新索引时，确认每个被引用文件都存在。
   - 阅读并刷新本次请求影响到的每个被索引支持文件。
   - 保留支持文件中的警告，除非它们过时、被当前事实反驳，或用户要求删除。
   - 删除支持文件中过时的命令、路径和链接。
   - 修改支持文件时，如果用途或路径变化，同步更新索引条目。
   - 修复或移除失效链接，不要留下死路由。
   - 检查父级、嵌套文件、支持文件之间是否存在冲突指令。

5. **验证最终文档**
   - 重新阅读已编辑的 `AGENTS.md` 和被索引文件。
   - 尽可能确认命令来自真实的仓库配置或文档。
   - 确认最终结构能告诉 agent：不同任务类型应该读取哪些文件。

## 推荐的根 `AGENTS.md` 结构

只使用适合当前仓库的章节：

```markdown
# AGENTS.md

## 项目概览
[2-5 条要点：用途、技术栈、重要边界]

## 如何导航这些指令
- 从这里开始读取仓库级规则。
- 如果任务涉及 `path/`，还要读取 `path/AGENTS.md` 或 `docs/agents/path.md`。
- 除非任务跨越多个领域，否则不要加载无关子系统说明。

## 仓库地图
- `path/` — 用途；本地规则见 `path/AGENTS.md`。

## 常用命令
- 安装：`...`
- 构建：`...`
- 测试：`...`
- Lint / 类型检查：`...`

## 工作规则
- 遵循被修改子树中的现有模式。
- 让修改范围贴合用户请求。
- 行为变化时添加或更新测试。

## 索引指导
- [测试](docs/agents/testing.md) — 添加测试或排查失败时阅读。
- [部署](docs/agents/deployment.md) — 修改发布 / 部署相关代码时阅读。
```

## 内容应该放在哪里

| 内容 | 放置位置 |
|---|---|
| 适用于仓库内所有任务 | 根 `AGENTS.md` |
| 只适用于某个目录 | 嵌套 `path/AGENTS.md` |
| 很长的命令矩阵或故障排查指南 | 从 `AGENTS.md` 链接到的 `docs/agents/*.md` |
| 面向人的产品背景 | README 或普通文档；只摘要 agent 需要知道的部分 |
| 生成的、过时的、推测性的笔记 | 不要放入指令集 |

## 被索引的支持文件

当细节太长或只在特定条件下有用，不适合放进根文件时，使用支持文件。常见候选：
- `docs/agents/testing.md`
- `docs/agents/frontend.md`
- `docs/agents/backend.md`
- `docs/agents/deployment.md`
- `docs/agents/security.md`

每个支持文件都应以类似结构开头：

```markdown
# [主题] Agent 指导

当 [具体触发条件] 时阅读本文。

## 关键命令
...

## 本地规则
...

## 来源
- `path/to/source-doc.md`
```

“当……时阅读本文”很重要：它让未来的 agent 在加载细节前判断这个文件是否相关。

更新支持文件时：
- 确认每个文件仍有清晰的触发说明。
- 从当前仓库文档 / 配置刷新内容，不要依赖记忆。
- 保持 `AGENTS.md` 中的索引描述与文件内容一致。
- 如果指导来自其他文档或配置，列出来源。

## 更新已有指令

当 `AGENTS.md` 已存在时：
- 把它视为有意写下的项目上下文。
- 尽可能原样保留强指令和警告。
- 把新信息合并到现有章节，而不是为了风格重写整份文件。
- 如果把细节移动到支持文件，在原位置留下简短索引条目。
- 如果删除或修改了非显然的指令，在最终回复中说明。

## 常见错误

| 错误 | 更好的做法 |
|---|---|
| 把所有包级细节都塞进根文件 | 根文件索引包级文件；包级文件存放本地细节 |
| 只添加链接但不创建 / 更新目标文件 | 同一次修改中保证每个索引条目都是活的 |
| 整段复制 README | 只提取 agent 相关的命令、规则和坑点 |
| 编造命令 | 阅读配置 / 文档；无法确认时标注未知，不要猜 |
| 忽略嵌套优先级 | 对某个子树而言，最近的 `AGENTS.md` 覆盖父级说明 |
| 刷新时删除旧指导 | 除非过时、冲突或用户要求删除，否则保留 |

## 最终回复

总结：
- 创建或修改了哪些 `AGENTS.md`
- 创建或修改了哪些被索引的支持文件
- 哪些命令或链接无法验证
- 解决了哪些父级 / 嵌套指令冲突
