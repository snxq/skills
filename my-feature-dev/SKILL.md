# my-feature-dev

功能迭代多任务开发的编排流程：阶段规划 → 公共依赖先行 → 子 Agent 并行开发（worktree）→ 子 Agent 审查 → MR 管理。主会话是组织者与上下文管理者，不直接写业务代码。

## 何时使用

一个迭代/版本内有多个后端开发任务（数据层、任务改造、多个接口），需要有序并行推进并各自评审合入时。

## 核心约定

1. **基于 origin 的迭代基线分支为起点**：任务分支以 `origin/<迭代基线分支>`（已含先行件）为起点，不基于本地特性分支，避免 MR diff 携带无关提交。
2. **用 worktree 创建分支**：每任务独立 `.worktrees/<分支名>`，并行互不干扰。
3. **尽量用子 Agent 执行具体工作**：建 worktree、开发、提交、建 MR 均由子 Agent 执行。
4. **尽可能并行子 Agent**：无依赖任务同一批派发；每个子 Agent 独立 worktree、零文件重叠。
5. **主会话负责组织与上下文管理**：阶段规划、任务书编写（基线、目录、MR 目标都写清楚）、对审查结论裁决；**对子 Agent 产出的审查另起子 Agent 执行**，主会话不自己读码。

## 输入文档依赖（开工前收集齐全）

| 文档 | 用途 |
| --- | --- |
| 需求规格（PRD） | 业务口径、判定规则、验收标准 |
| 需求原型 | 页面交互、数据范围、字段语义 |
| 后端技术方案 | 数据层设计、接口设计、计算任务设计 |
| 前端接口对接文档 | 前后端契约：请求/响应字段、枚举、异常返回的**权威定义** |
| 后端工作内容 | 工作项清单、依赖、交付物 |

**权威优先级（字段/口径冲突时）**：前端接口对接文档 > 后端技术方案 > 需求规格/工作内容。文档自身标注差异处以前端文档为准，并在 MR 描述注明。

## 流程

### 1. 阶段规划（由具体项目分析，非模板）

- 画工作项依赖图：编号 → 依赖 → 人日 → 交付物。
- 区分三类：
  - **先行件**：所有下游依赖的公共层变更（数据模型/常量/公共枚举等），必须最先完成并合入。是否涉及数据层由项目实际情况决定。
  - **关键路径**：被最多下游依赖的任务。
  - **独立件**：只依赖先行件、可并行。
- 阻塞项（外部接口字段、调度参数确认等）单独列清单，标注关闭时机。
- 文档先行（L0 类）：接口对接文档 Day1 输出，前端可 mock 并行，不阻塞后端。

### 2. 先行件落地

- 公共层变更先行完成：与设计文档逐项核对产出；需运营可调的值做成「默认值 + 配置项 + 按次读取」；既有公共资产复用不重定义。
- 先行件独立 MR，先行 review 合入迭代基线分支。

### 3. 并行任务开发（子 Agent 执行）

主会话为每个任务编写任务书，**在上下文中描述清楚，由子 Agent 自行执行建 worktree、开发、提交、建 MR**。任务书必备：

- 任务目标、范围与明确不做项；
- 参考文档路径 + 相关章节（注明权威优先级）；
- **基线**：`origin/<迭代基线分支>`；**worktree 目录**：`.worktrees/<分支名>`；**分支名**；
- 先行件资产清单（DAO、常量、配置读取方式等已就绪的依赖）；
- 校验约定（编译 + lint 全量、区分新增/既存问题、不跑全量测试）；
- 提交约定（提交信息规范）；**MR 约定**（目标分支、标题格式、描述要素：依据文档/变更内容/验证/确认点）。

任务间文件零重叠。

### 4. 审查（另起子 Agent）

- 每个开发子 Agent 完成后，**另起审查子 Agent**：提供任务书、权威文档、产出分支/MR 链接，按审查清单输出结论（问题分级：阻断/建议/确认点）。
- 主会话裁决：哪些问题需要修（修在任务分支上），哪些进联调确认点，裁决后推进合入。

审查清单（通用维度）：

- 口径一致性：新计算是否复用既有函数/算法，"另写一套"（类型转换、不同算法）是危险信号；
- 重算回写链路：逐行字段按各行自己的日期/序列计算，不能以计算日值覆盖历史行；
- 权威文档对齐：请求/响应字段、枚举、必填项逐项核对；
- 边界：空值/无数据、幂等与并发、软删过滤；
- 关联可行性：外键/join 形态用真实数据实测；
- 生成器注册完整性：新增包/资源必须出现在生成器的聚合与注册文件（如 blank import 列表、service 注册入口）中，这类"应改未改"的缺失不在 diff 里，静态检查（编译/lint）无法发现；
- 运行时冒烟：编译通过 ≠ 服务可运行；注册、中间件、路由绑定等都是运行时行为，验收须真实启动服务并实际调用一次新接口；
- 风格规范：分层、中文注释、错误处理、标签精简。

### 5. MR 管理

- 先行件 MR 先行合入迭代基线；任务 MR 互不依赖、可任意顺序合入。
- 每个任务 MR 创建后验证：ahead = 任务自身提交数、behind = 0、diff 不含先行件内容。
