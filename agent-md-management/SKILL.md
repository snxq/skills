# AGENTS.md 管理

创建或更新仓库的 `AGENTS.md` 指令文件，让未来的 agent 获得正确上下文，而不是一次性加载整个项目的全部细节。

## AGENTS.md 的加载机制

`AGENTS.md` 是开放格式（agents.md 规范，由 Linux Foundation 下的 Agentic AI Foundation 维护），纯 Markdown、无必需字段；主流编码 agent（codex、opencode、cursor、gemini、zed 等）都会读取。理解加载行为是管理它们的前提：

- **根 `AGENTS.md`**：仓库根目录的 `AGENTS.md` 在会话启动时自动加载，适用于整个仓库及其所有子目录。
- **嵌套 `AGENTS.md`**：下级目录中的 `AGENTS.md` 只作用于该目录及其子目录，agent 处理该目录中的文件时才会读取，其余任务不承担它的上下文开销。
- **就近优先**：指令冲突时，离目标文件最近的 `AGENTS.md` 生效；用户的显式会话指令高于一切。
- **向上回溯**：部分实现（如 opencode）从当前目录向上遍历，遇到第一个 `AGENTS.md` 即加载——嵌套文件同样满足按需原则。

## 核心原则

把根 `AGENTS.md` 当作简洁的导航层，而不是文档垃圾桶。README 面向人类，`AGENTS.md` 面向 agent，二者互补、不要互相复制。把所有任务都需要知道的规则放在根 `AGENTS.md`；把详细、条件性、子系统专用的说明放到下级目录的嵌套 `AGENTS.md` 或外部引用文件中。

## 何时使用

以下请求应使用此 skill：
- 创建 / 初始化 / 编写 `AGENTS.md`
- 更新 / 刷新 / 审计已有 agent 指令
- 创建或管理下级目录中的嵌套 `AGENTS.md`
- 组织 monorepo 或包级别的 agent 指导
- 减少 agent 文档的上下文膨胀
- 创建或更新 `AGENTS.md` 引用的文件

不要把它用于普通 README 写作，除非 README 会作为 agent 指令的来源。

## 工作流程

1. **先读再写**
   - 阅读目标范围内已有的 `AGENTS.md`（根文件与相关嵌套文件）。
   - 阅读这些文件引用或导入的外部文件。
   - 检查项目文档和配置，用来验证命令、约定和工作流。
   - 保留明确的用户 / 项目指令，除非用户要求删除，或它们已经明显过时。

2. **选择作用域**
   - 根 `AGENTS.md`：仓库级概览、共享命令、共享规则——每次会话都加载，保持简短。
   - 嵌套 `path/AGENTS.md`：某个子树的本地说明——按需加载，就近优先。
   - 外部文件引用：在 `AGENTS.md` 中引用 README、`docs/` 等详细文档，避免复制内容。

3. **应用渐进披露**
   - 保持根 `AGENTS.md` 简短、易扫读。虽然格式没有硬性长度限制，但越短的文件遵守度越高。
   - 把细节放到下级目录的嵌套 `AGENTS.md`，利用按需加载机制，而不是塞进根文件。
   - 子系统专用说明放到对应子树的 `AGENTS.md`；详细文档用引用而非整段复制。
   - 如果 `AGENTS.md` 引用了某个文件，要在同一次修改中创建或更新该文件。

4. **更新整套指令集**
   - 更新时确认每个被引用文件都存在。
   - 阅读并刷新本次请求影响到的每个嵌套 `AGENTS.md`。
   - 保留指令中的警告，除非它们过时、被当前事实反驳，或用户要求删除。
   - 删除过时的命令、路径和链接。
   - 修复或移除失效的外部引用路径。
   - 检查根 `AGENTS.md` 与嵌套文件之间是否存在冲突指令（就近优先规则下，冲突默认以更近的文件为准）。

5. **验证最终文档**
   - 重新阅读已编辑的所有文件。
   - 尽可能确认命令来自真实的仓库配置或文档。
   - 确认最终结构能告诉 agent：不同任务类型应该读取哪些文件。

## 推荐的根 `AGENTS.md` 结构

只使用适合当前仓库的章节；官网统计的常用章节为：项目概览、构建与测试命令、代码风格、测试说明、安全注意事项：

```markdown
# AGENTS.md

## 项目概览
[2-5 条要点：用途、技术栈、重要边界]

## 常用命令
- 安装：`...`
- 构建：`...`
- 测试：`...`
- Lint / 类型检查：`...`

## 代码风格
[关键约定；细节指向 docs/ 或对应嵌套文件]

## 测试
[测试命令之外的约定：覆盖要求、运行方式]

## 安全
[必须遵守的安全红线]

## 工作规则
- 遵循被修改子树中的现有模式。
- 让修改范围贴合用户请求。
- 行为变化时添加或更新测试。

## 仓库地图
- `path/` — 用途；本地规则见 `path/AGENTS.md`。
```

列出的测试命令会被 agent 实际尝试执行并修复失败（agents.md 官方 FAQ），因此命令必须可验证、来自真实配置——编造命令会直接导致错误操作。

## 内容应该放在哪里

| 内容 | 放置位置 |
|---|---|
| 适用于仓库内所有任务的简洁规则 | 根 `AGENTS.md` |
| 只适用于某个下级目录的说明 | 嵌套 `path/AGENTS.md` |
| 某个子系统的详细规则（API、前端、测试等） | 对应子树下的嵌套 `AGENTS.md` |
| 已有的外部文档（README、`docs/`、`CONTRIBUTING.md` 等） | 用引用导入到 `AGENTS.md`，不要整段复制 |
| 面向人的产品背景 | README 或普通文档；只摘要 agent 需要知道的部分 |

## 嵌套 `AGENTS.md`（下级目录）

嵌套文件是渐进披露的核心机制：agent 处理 `path/` 下的文件时才会读到 `path/AGENTS.md`，其余任务不受噪音干扰。指令冲突时以离目标文件更近的文件为准。

```markdown
# backend/AGENTS.md

- API 端点必须校验输入
- 错误响应统一为 `{ "error": string, "code": number }`
- 数据库迁移必须可回滚
```

### 推荐的嵌套位置

按需创建，不要预设全部：
- `backend/AGENTS.md`、`frontend/AGENTS.md` — monorepo 各子项目
- `src/api/AGENTS.md` — 特定子系统
- `infra/AGENTS.md` — 部署 / 基础设施约定
- `packages/<name>/AGENTS.md` — 工作区包级规则

## 引用外部文件

根文件保持简短的同时，要让 agent 能找到详细文档。

### `@` 导入

部分实现原生支持在 `AGENTS.md` 中用 `@path/to/file` 导入其他文件（如 codex；单文件引用，有的实现还支持目录与 glob）：

```markdown
# AGENTS.md

@docs/architecture.md
```

注意：`@` 导入不是所有 agent 都支持（例如 opencode 不会自动展开）。使用前确认目标 agent；关键指令不要只存在于被引用文件中，根文件里应保留一句摘要。

### 按需读取指令

对不自动解析引用的 agent，在 `AGENTS.md` 中写明引用约定，让 agent 按需加载：

```markdown
## 外部文件
遇到 `@path` 引用时，用 Read 工具按需读取对应文件，不要预加载全部引用。
- 测试约定：@docs/testing.md
- 架构说明：@docs/architecture.md
```

## 迁移与多工具兼容

`AGENTS.md` 是跨工具标准，各工具自己的指令文件可以指向它，避免维护多份副本：

- 重命名旧文件：`mv AGENT.md AGENTS.md && ln -s AGENTS.md AGENT.md`
- Claude Code：`ln -s AGENTS.md CLAUDE.md`（Linux）
- Aider：在 `.aider.conf.yml` 中配置 `read: AGENTS.md`
- Gemini CLI：在 `.gemini/settings.json` 中配置 `{ "context": { "fileName": "AGENTS.md" } }`
- 其他工具：保留软链接，让各 agent 读取同一份内容。

## 更新已有指令

当 `AGENTS.md` 已存在时：
- 把它视为有意写下的项目上下文。
- 尽可能原样保留强指令和警告。
- 把新信息合并到现有章节，而不是为了风格重写整份文件。
- 如果把细节移动到嵌套 `AGENTS.md`，在原位置留下简短说明。
- 如果删除或修改了非显然的指令，在最终回复中说明。

## 常见错误

| 错误 | 更好的做法 |
|---|---|
| 把所有细节都塞进根 `AGENTS.md` | 把子系统细节放到下级目录的嵌套 `AGENTS.md`，按需加载 |
| 整段复制 README | 用引用导入，或只摘要 agent 需要的部分 |
| 编造命令 | 阅读配置 / 文档；无法确认时标注未知，不要猜 |
| 忽略嵌套优先级 | 记住就近优先：离目标文件最近的 `AGENTS.md` 生效 |
| 关键指令只写在被引用文件里 | 根文件保留一句摘要；依赖 `@` 导入前确认 agent 支持 |
| 刷新时删除旧指导 | 除非过时、冲突或用户要求删除，否则保留 |

## 最终回复

总结：
- 创建或修改了哪些 `AGENTS.md`（根与嵌套）
- 引用了哪些外部文件、哪些引用无法验证
- 哪些命令或链接无法验证
- 解决了哪些指令冲突
